# Internationalization model

Portfolio Architect separates machine data, integration translations, and
Lovelace presentation.

## Machine layer

The calculation engine emits language-neutral keys and states. Stable user-owned target IDs,
policy rule IDs, allocation states, WKNs, and ISINs never depend on translated
display strings. The historical `fund_id` key is a compatibility alias for the same target identity.

## Home Assistant entity layer

Entity names, states, state-attribute labels, and icons use Home Assistant
translation keys. Native entity states follow the active user's frontend
language.

## Dashboard layer

Literal Lovelace titles and Markdown are static configuration. v0.5.4 therefore
ships two complete, maintained views:

- `dashboard/en/view.yaml` — English;
- `dashboard/de/view.yaml` — German.

`dashboard/bilingual-dashboard.yaml` combines both views in one dashboard. The
English view is first and acts as the default reference view. Users switch the
literal dashboard language by selecting the corresponding view tab. Both views
use the same language-neutral entities, so no calculations or data are
duplicated.

The language shortcut badge still opens `/profile/general` for changing native
Home Assistant entity-state localization.

## Security rationale

The bilingual-view design uses only native Lovelace configuration. It does not
inject JavaScript, write profile settings, create helpers, call services, or
store a user-selected language in shared Home Assistant state.


## v0.5.4 view-language isolation

Home Assistant translates native entity states according to the active user
profile, not according to the selected Lovelace view. A German static view can
therefore display English binary-sensor states for an English-profile user.
v0.5.4 avoids that ambiguity without custom JavaScript or duplicate entities:
target-position state text is hidden, state-driven icons remain, and each view
supplies its own static legend.

The top-level views are labelled `EN` and `DE` and no longer use icons. Home
Assistant otherwise displays only the icon for a view unless icon-and-title
display is explicitly enabled.


## v0.6.0 native monthly plan

Monthly plan and runtime-health entities use translation keys in the integration.
The bilingual dashboard uses view-local static names on conditional status tiles,
so English and German status wording does not depend on the user's profile
language. Numeric, currency, version, and timestamp states remain language-neutral
and are formatted by Home Assistant.

## v0.7.0 native policy compliance

Policy entity names, enum states, attribute labels, policy value tokens, and
known exception rationale IDs are translated in English and German. The engine
continues to emit language-neutral rule IDs and machine values. The bilingual
dashboard uses explicit EN/DE labels and hides profile-dependent enum states
where static view localisation is required.

## v0.8.0 native allocation and review semantics

Per-position allocation status entities use language-neutral states
`underweight`, `on_target`, and `overweight`, translated by Home Assistant.
Dashboard view text remains maintained in matched English and German variants.
Exception review entities distinguish future, overdue, and last-decision dates
without translating or reusing machine identifiers in program logic.

## v1.1 custom-integration translations

The custom integration ships complete runtime translation files at
`translations/en.json` and `translations/de.json`. Config-flow, reconfigure,
options, entity, state, and attribute keys are matched across both languages.
No translated string is used as a file path, identifier, scope, policy rule, or
calculation input.

## v1.2 native plan configuration

The options flow, menu, recurring schedule selectors, validation errors, reset
confirmation, new plan entities, enum states, and diagnostic attributes ship in
matched English and German translations. Dynamic instrument choices use the
validated instrument name and WKN only, avoiding an English-only instrument-type
label. Frequency and budget-basis values remain language-neutral machine states
and are translated only by Home Assistant.
