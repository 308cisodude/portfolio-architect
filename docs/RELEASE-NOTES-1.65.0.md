# Portfolio Architect v1.65.0 — DKB read-only shadow snapshot

The successful v1.64.5 live response showed an explicit ISIN in DKB's `:35B:` instrument field, while PyFinTS 5.0.0 did not populate its `ISIN` attribute. This release projects the explicit bounded bank-field ISIN into an in-memory read-only shadow row. If the bank-field and library ISIN disagree, the normalized ISIN is unavailable and the conflict is visible. WKN-only or malformed fields never become an ISIN.

The DKB admin Ingress now presents independent CSV and FinTS rows as responsive cards with wrapped identifiers. A shadow summary counts positions with bounded ISIN, quantity, total value and currency; it does not compare sources or decide equivalence. A status line shows whether bank approval is pending, a shadow detail is available, or a manual refresh is needed. Successful detail remains in App memory for only five minutes. The persisted research outcome remains count/time/code only; position identifiers, values, bank response and credentials are never persisted or exposed through REST status, health, Home Assistant or logs.

The existing one-shot request remains user-initiated, for exactly one UPD-authorized depot, read-only and challenge-aware. There is no background polling, credential storage, planner integration, acquisition-source switch, CSV fallback or wire-schema change. DKB CSV holdings and cash remain authoritative. A valid empty response shows zero positions; ambiguous or failed responses do not create shadow detail. Multiple eligible depots still stop before a request.
