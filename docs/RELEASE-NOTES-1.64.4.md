# Portfolio Architect v1.64.4 — transient DKB holdings evidence view

After the live v1.64.3 HKWPD request retrieved one holding from one authorized depot, this release makes the two evidence sources available for human review in DKB admin Ingress. It displays independent CSV and FinTS tables with ISIN, quantity, position value, currency availability and source time. There is no automatic matching, difference score, tolerance or conclusion. Differences may be plausible because the CSV is a static export and FinTS is live.

The DKB CSV provides a date-only export field, quantity and an EUR position value derived by its existing importer. The FinTS table shows the live observation UTC time and the parser's optional price date, pieces and total holding value. PyFinTS 5.0.0 does not expose the currency of `Holding.total_value`; that column is explicitly unavailable. A price date is not presented as a holdings snapshot timestamp. The current CSV snapshot may aggregate multiple depot exports, while the FinTS probe reads exactly one authorized depot; the UI identifies each source independently and makes no depot-level equivalence claim.

The display is bounded to 64 rows per source, held only in App memory for five minutes after retrieval, and cleared on a new observation, CSV holdings import, product-registration change, expiry or App restart. If the source is missing or exceeds the view bound, the corresponding detail is unavailable. FinTS position identifiers, quantities and valuations never enter the persisted research observation, REST/health status, logs or Home Assistant. The request still makes at most one read-only HKWPD operation. DKB CSV remains the sole authoritative holdings and cash source; no planner, acquisition, fallback, wire schema or dashboard change occurs.
